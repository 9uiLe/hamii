## Candidate semantics, derived without treating the mapping as implemented

The contract has three semantic inputs: `profile.renderable: Bool`, `profile.displayName: String?`, and `profile.createdAt: Instant?`. Both outputs are visible only when `renderable == true`. I01 is the identity of a nonnil display name; its nil case is explicitly `needsResolution`, so the candidate does **not** define a display string for a renderable profile with nil name. I02 is the UTC Gregorian `yyyy년 M월 d일 가입` rendering of a nonnil instant and the exact literal `가입일 정보 없음` when the instant is nil. These statements come from `packets/R/relation-R.json:3-21` and `packets/R/transform-registry.json:3-11`.

| Probe | Semantic inputs and visible I01 | Visible I02 | Dependencies / consequence |
| --- | --- | --- | --- |
| P0 first load, no renderable profile | `renderable=false`; I01 hidden, regardless of display name | Hidden, regardless of createdAt | Only `profile.renderable` matters to visibility. No fallback text should appear merely because the profile is absent. |
| P1 refresh loading, cached profile | `renderable=true`; I01 visible as cached `displayName` if nonnil; nil remains unresolved | Visible as formatted cached `createdAt` if nonnil, otherwise `가입일 정보 없음` | Loading is not a relation input. Both outputs continue to depend on the last-known values and renderability. |
| P2 refresh failure, cached profile | Same as P1: cached name or unresolved nil | Same as P1: cached formatted date or nil literal | Failure is not a relation input; retaining the cached semantic inputs preserves output. |
| P3 loaded profile, nil createdAt | `renderable=true`; I01 visible as loaded `displayName` if nonnil; nil unresolved | Visible as `가입일 정보 없음` | I01 depends on `displayName` and renderability; I02 depends on `createdAt` and renderability. |
| P4 loaded profile, nonnil createdAt | `renderable=true`; I01 visible as loaded `displayName` if nonnil; nil unresolved | Visible as the given instant's UTC Gregorian date in `yyyy년 M월 d일 가입` form | Actual strings require the probe's name and instant; the packet supplies neither concrete value. |

The table does not equate an empty string with nil: identity preserves an empty `String` if supplied. The contract does not define loading/error state, caching, source priority, or an output placement. `whenNil` is reached only for a *visible* relation; hidden output has no displayed fallback.

## Proposed Team MINO mapping versus existing source

`packets/R/repository-mapping.json:3-19` explicitly calls itself a proposed integration mapping. It proposes presence of a last-known `Profile` for renderability, `Profile.nickname` through `ProfileMainState.nickname` for display name, and retained `Profile.createdAt` for creation time. The actual Domain `Profile` has nonoptional `nickname` and optional `createdAt` (`Packages/Domain/Sources/Domain/Entities/Profile.swift:8-19`). Thus a real `Profile` currently supplies a nonnil I01 name, but the more general candidate still leaves its optional-name nil case unresolved.

Current `ProfileMainState` contains `nickname: String` and `avatarColor`, initializes `nickname` to `""` without a profile, and drops both profile presence and `createdAt` (`Packages/FeatureProfile/Sources/FeatureProfile/Main/ProfileMainStore.swift:20-25,40-55`). On success, its reducer replaces only nickname and avatar; on failure, it changes nothing (`ProfileMainStore.swift:108-130`). The coordinator seeds the Store from `lastKnownProfile` and holds it across tab transitions (`Packages/FeatureProfile/Sources/FeatureProfile/ProfileCoordinator.swift:60-87`); refresh is sent on visible entry and app activation (`Packages/FeatureProfile/Sources/FeatureProfile/ProfileTabView.swift:35-75`). Existing tests confirm seeded values and retained nickname/avatar after failure (`Packages/FeatureProfile/Tests/FeatureProfileTests/ProfileCoordinatorTests.swift:63-82`; `Packages/FeatureProfile/Tests/FeatureProfileTests/ProfileMainReducerTests.swift:54-74`). Existing view always builds the nickname edit row and has no I02 row (`Packages/FeatureProfile/Sources/FeatureProfile/Main/ProfileMainContentView.swift:33-78,80-124`). Therefore neither the contract's visibility gate nor I02 is an implemented feature, and the current empty nickname is not a reliable presence marker.

The in-memory last-known repository retains the whole `Profile` for one app run (`Packages/Data/Sources/Data/Repositories/InMemoryLastKnownProfileRepository.swift:4-29`); fetch/register/update use cases save successful profiles there (`Packages/Domain/Sources/Domain/UseCases/ProfileUseCases.swift:18-36,39-89`). It can seed both date and presence, but `ProfileMainState` currently discards them. `ProfileDTO.createdAt` is nonoptional while Domain `Profile.createdAt` is optional (`Packages/Data/Sources/Data/DTO/ProfileDTO.swift:8-24`): nil is representable in Domain/test paths, but a missing/null network date currently fails DTO decoding before the contract's I02 nil literal can be shown.

## Safe implementation assessment

A safe direction is to retain an explicit last-known profile presence and its `createdAt` alongside nickname at initialization and on `.profileLoaded`, leave all three unchanged during `.loadProfile` and `.profileLoadFailed`, derive I01/I02 visibility from presence, and format a nonnil `Date` with explicit Gregorian calendar and UTC timezone. Add reducer and view checks for P0-P4, especially failed refresh with cached nil and nonnil dates, and avoid using `nickname.isEmpty` as a presence test. This follows the target's State/reducer/View division and test convention (`.claude/docs/mvi-coordinator-di.md:241-265,351-362`) and its Feature-to-Domain dependency boundary (`.claude/docs/clean-architecture.md:3-21`).

There is **no unique source-level patch**. A stored `Profile?`, a separate presence flag plus `Date?`, or a presentation value object can all carry the necessary information. Exact insertion point, whether I01/I02 replace or augment existing UI, and final Product copy are not provided. The candidate's nil display-name branch needs a policy if another source can emit nil. The Spike transform explicitly says its Korean date copy is not final Product copy (`packets/R/transform-registry.json:5-11`). A decision is also needed on whether a nil network `createdAt` must be accepted by `ProfileDTO`; changing DTO decoding is outside the state-only mapping.

Cached behavior is preservable: the existing reducer already keeps nickname/avatar on refresh start/failure, and the coordinator keeps the Store alive. The new presence/date must share those same transitions. Merely mapping `Profile.createdAt` without carrying it into State would lose the date on every render. The contract contains no Team MINO layer, store, DTO, or coordinator identifier: the Product mapping is isolated in a separate proposed file. Its `profile.*` semantic vocabulary and Spike-only presentation format do not impose Team MINO architecture on the contract. The relation's declared source and `visibleWhen` source are enough to identify update dependencies: change to renderability can show/hide both; change to display name updates I01; change to creation instant updates I02. No separate invalidation field is needed for that dependency graph, though the runtime must actually reevaluate on source changes and the packet does not prescribe its observation mechanism.
