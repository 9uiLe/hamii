## Findings and required corrections

1. **Medium — Exact matrix coverage is not enforced by the evaluator.** `evaluate.py:121-129` iterates whatever cases are supplied, and `evaluate.py:160-161` requires only ten matched rows. In an in-memory mutation, replacing P4 with a second P3 still yielded 10/10 and passed the main gate. The delivered packet has the correct matrix, but the executable check cannot prevent a missing P4. Require unique case IDs exactly `{P0,P1,P2,P3,P4}` and expected output keys exactly `{I01,I02}` before rendering; also assert each `(case, output)` pair appears once.
2. **Medium — Mapping presence is weaker than mapping validity.** `evaluate.py:90-94` checks only key existence. An in-memory mapping with `profile.renderable: {}` still produced sufficient P1 output for both candidates at 2026-10-01T12:12:00Z. The actual mapping openly says `mappingStatus` is proposed (`repository-mapping.json:3-4`) and marks renderability/date retention as requiring implementation (`repository-mapping.json:6-9,16-19`). Report the negative result narrowly as *missing key fails closed*; validate mapping schema/status and verify implementation before claiming integration safety.
3. **Low — Type and architecture guards are incomplete.** R normalization checks source names but not declared types (`evaluate.py:27-45`); G normalization checks node roles but not their declared types (`evaluate.py:48-74`). In-memory substitutions of `Product.Profile.createdAt` as R's declared type and `Product.String` as a G output type were accepted. The leakage check is a five-token substring scan (`evaluate.py:140-141`). The current R/G files are clean, but that check does not prove a general prohibition on Product-specific architecture. Validate an allowed semantic type vocabulary and candidate schemas, or phrase `productArchitectureLeakage: []` as a bounded observation about the current documents.
4. **Low — Runtime implications are outside this test.** `evaluation.json:181,366` reports `separateUpdateTriggerNeededForTheseCells: false`; the evaluator sets this constant in `evaluate.py:147` and does not exercise update propagation. P1/P2 are prepopulated snapshots (`oracle.json:18-27`), not cache-retention transitions. State these as representation-level conclusions only. Do not present cached behavior, update propagation, or the Spike-only date copy (`oracle.json:3-9`; `transform-registry.json:5-11`) as production guarantees.

No blocking defect was found in the current ten-cell oracle result. The medium findings affect the strength of the evaluator's reusable gates and the scope of claims drawn from them.
