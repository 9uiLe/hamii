## Proposed mapping versus existing source

`repository-mapping.json` labels its entries a **proposed integration mapping**. It proposes preserving whether a last-known `Profile` exists, mapping display name through `Profile.nickname`/`ProfileMainState.nickname`, and retaining `Profile.createdAt` across refresh. Only the nickname path is presently in screen state. The Domain `Profile` has a nonoptional nickname and optional `createdAt`; `ProfileDTO` requires a date and maps it into `Profile`, while test fixtures can construct `Profile` with nil date. Thus the target's current API path normally supplies a date, but the candidate's nil-date branch remains meaningful for the Domain type and tests. ## Safe source-level plan and remaining decisions

The patch is **not unique**. A straightforward option is to keep `Profile?` in `ProfileMainState`, seed it from the existing last-known use case, replace it only on `.profileLoaded`, and derive renderability, name, and date from that one snapshot in the view or a pure presentation helper. This keeps name/date/existence coherent across P0–P4 and leaves loading/failure as no-op for the snapshot. Another viable shape is separate state fields plus an explicit `hasProfile` boolean, updated atomically. Do not infer renderability from empty nickname: that conflates no profile with a present profile whose name is empty. `Profile.nickname` being nonoptional makes the proposed Team MINO I01 mapping total for current source values, but the abstract candidate still needs its `String?` nil rule resolved before claiming a complete cross-target contract. [ProfileMainStore.swift](../../targets/team-mino/Packages/FeatureProfile/Sources/FeatureProfile/Main/ProfileMainStore.swift#L20-L55), [Profile.swift](../../targets/team-mino/Packages/Domain/Sources/Domain/Entities/Profile.swift#L8-L19), [graph-G.json](../packets/G/graph-G.json).

Before a production patch, decide I01's nil behavior, final Product copy/date presentation and placement, and whether the visibility gate hides only I01/I02 or the existing entire profile summary. Keep UTC explicit if using the registry transform; device locale/time zone defaults would diverge. Add transition coverage for no cache, loading/failure with cache, nil date, and nonnil date. Existing tests cover cached nickname/avatar and refresh failure but not renderability/date. Respect the target convention: Feature manages screen state and presentation; Domain provides `Profile`/use cases; the view receives state and `send` rather than fetching. [ProfileMainReducerTests.swift](../../targets/team-mino/Packages/FeatureProfile/Tests/FeatureProfileTests/ProfileMainReducerTests.swift#L23-L75), [ProfileCoordinatorTests.swift](../../targets/team-mino/Packages/FeatureProfile/Tests/FeatureProfileTests/ProfileCoordinatorTests.swift#L54-L83), [clean-architecture.md](../../targets/team-mino/.claude/docs/clean-architecture.md#L3-L21), [mvi-coordinator-di.md](../../targets/team-mino/.claude/docs/mvi-coordinator-di.md#L67-L123).
