# Independent audit: slot conflict priority

The [checklist](CHECKLIST.md) was fixed before the new results were read. This audit uses only the [priority probe](../priority-evaluator/probe.swift), its [raw result](../priority-evaluator/result.json), the [Application boundary probe](../application-boundary/Probe.swift), its [raw result](../application-boundary/result.json), and production source. The probes' README and Spike conclusion were not used.

## Verdict

1. **Existing errors: partial preservation with known priority divergences.** The test-only A evaluator checks selected Variant/API validity, then same-path selected Variant conflicts, then selected Variant/property writes to removed slot descendants, then calls the current Resolver. Its 18/18 `passed` cases compare selected summary fields or error codes. For the fixed single-error cases it retains `unknownVariant`, `unknownProperty`, `unknownSlot` for a missing slot name, `forbiddenOverride`, `conflictingVariants`, and a property-kind `unknownPath`. It leaves the public removed-path `allowedOverride` to the current Resolver, which returns `unknownPath`. But in the mixed `conflictingVariants` plus non-public override case, the candidate returns `forbiddenOverride` while the current Resolver returns `conflictingVariants`. Thus preserving both rejection categories separately does **not** preserve the current error priority. The A evaluator also returns `slotWriteConflict` for the renamed outer-first nested slots before the current Resolver's `unknownSlot(zInner)` can occur. The exact priority contract remains undecided.
2. **Allowed override: unchanged in the candidate code, not yet a production guarantee.** A's `selectedWritePaths` deliberately excludes `allowedOverrides`, then invokes the current Resolver. The fixed public removed-path case still returns `unknownPath`, and the disjoint non-public override returns `forbiddenOverride`. It does not test all mixed override/slot/Variant error combinations. Unlike the prior naive slot-wins evaluator, it does not drop an override value. No production Resolver change exists in this artifact.
3. **Unselected Variant: no false-positive in fixed candidate output; observability limited.** A's unselected-Variant case and B's `variant_unselected_both_slots_selected` case produce no test-only conflict. Both select slots that remove the Variant's target. Consequently the resolved output alone cannot demonstrate that the dormant Variant was not applied; the probe's selection logic, rather than an observable retained target, supports the no-conflict claim. A's selected outside Variant confirms a disjoint write survives, and selected Variant without a slot retains its text.
4. **Strict ancestry: implemented in A's prototype for the exercised tree.** `strictlyContains` starts from children and uses exact `EntityID` comparison, so the slot target itself is excluded. Fixed cases cover direct/nested descendants and an outside sibling. They do not exercise similarly prefixed IDs, duplicate IDs, or a valid mutable field on the container itself; current `.text` paths cannot validly write a stack slot target. B's separate test-only `contains` includes the target itself and is safe only for its old-text descendant fixture. It should not be promoted as the strict-descendant algorithm.
5. **Nested selected slots: membership stable, runtime behavior not stable.** A reports the full sorted slot-name set (`inner`, `outer`) for an old-text write when both are selected; reversing dictionary insertion keeps that set. Renaming the slots so outer sorts first reports (`aOuter`, `zInner`). B independently reports both members for either name order. Yet current Resolver accepts inner-first and silently removes the write, while outer-first removes the inner target before its turn and throws `unknownSlot(z_inner)`; `DocumentValidator` emits `component.resolution` and Canonical save rejects. The candidate's outer-first `slotWriteConflict` is a changed diagnostic category, not proof that order has become harmless. A full selected-slot set is useful diagnostic information, but the policy for overlapping slot replacement and existing `unknownSlot` remains unresolved.
6. **ProjectService and Canonical boundaries: no slot-conflict mutation tested.** B creates valid Documents and directly calls `CanonicalRepository.commit`. Inner-first selected-write cases have zero `DocumentValidator` diagnostics, are accepted, and reopen equal to candidate. Outer-first has `component.resolution`, rejects, and its non-`.hamii` Canonical JSON path→bytes remains equal before and after the attempt. The test-only `gateRejected` is a Boolean checked **without calling** `ProjectService.mutate`; unchanged bytes/revision/ClientPrecondition across that check show only that no operation ran. The actual Service call is an unrelated `createPage`, which advances revision to 2 and changes Canonical bytes and precondition. Current public AuthoringIntent does not express this slot edit in the probe. It establishes Service liveness and token progression for a supported mutation, not production slot-conflict rejection. For direct Canonical rejection, path→bytes equality includes the manifest and thus supports unchanged persisted revision; it does not assert the private observation epoch stayed fixed.
7. **Test-only versus production: clear boundary.** A's `slotWriteConflict` is a string in a probe result, not a production `ComponentResolutionError` case, `DocumentValidator` rule, or common GUI/CLI mutation contract. B's conflict-slot detection is likewise an unintegrated pre-service function. No timing or generalized performance result is measured. The fixed matrices therefore support a priority decision discussion but cannot establish that the proposed rule has shipped.

## Decision-sensitive gaps

- Specify a deterministic diagnostic policy when a candidate has both selected-Variant path collision and a forbidden override. The test-only validity-first order differs from the current Resolver order.
- Specify whether an overlapping selected-slot conflict supersedes `unknownSlot` caused by outer-first materialization, or whether overlapping slots themselves are invalid. Test either rule through whole-Document validation and Canonical persistence.
- Make the unselected Variant negative control observable without deleting its target, and add an exact-ID prefix control if the ancestry algorithm is promoted.
- Implement and test the chosen rule in production `ComponentResolver`/`DocumentValidator` and the common Application Service path where a suitable intent exists. Verify rejected attempts' Canonical bytes and persisted revision without treating a no-op test gate as production integration.
