# Independent audit: slot write conflict boundary

The [checklist](CHECKLIST.md) was fixed before either new result was inspected. This review reads the [semantic probe](../semantic-alternatives/probe.swift), its [raw result](../semantic-alternatives/result.json), the [production-validation probe](../production-validation/Probe.swift), its [raw result](../production-validation/result.json), and the current production Resolver, Validator, and CanonicalRepository. The probes' README and Spike conclusion were not used as evidence.

## Verdict by checklist gate

1. **Descendant boundary: supported for fixed trees, not a general rule.** The test-only `selectedSlot` walks from the slot target to a path target using exact `EntityID` equality and requires positive depth. The raw structural controls show self distance 0, direct child 1, nested text 2, and outside sibling absent. That avoids a lexical-prefix error in this fixture. It does not establish behavior for duplicate IDs or all path kinds; the only candidate path shape exercised is `<id>.text`.
2. **Slot target itself: correctly separated from child loss.** Production `replaceChildren` retains the container and changes only `children`. B's resolved output retains `slot_container` with replacement child. A's `slotTargetText` is an unsupported `.text` write to a stack, and B rejects the same shape with `component.variantPath` and `component.resolution`. Neither result demonstrates a valid write to a slot target's own mutable property.
3. **Selected Variant and controls: bounded.** A shows selected `state=old` writes the old child and is then discarded by outer slot replacement. Its `unselected-variant-write` case selects `tone=outside`, leaving `state=old` unselected, but the old child is removed by the slot; the raw resolved tree cannot independently show whether that dormant write was skipped. B now separates `slot_unselected_selected_variant_inside_survives` (selected Variant, no slot) from `variant_unselected_slot_selected_no_write` (no selected Variant, slot present). The latter also removes the old child, so it is a useful fixture control but not an observable direct test that an unselected Variant had no effect. No two-axis equal-value collision is exercised in this new production probe; the prior Spike covers fixed same-path conflict cases.
4. **Empty replacement and multiple slots: observed, tie policy undecided.** A and B show a present slot key with `[]` removes old children; absence keeps them. With both inner and outer slots selected, production applies sorted slot names: `inner` replaces its children, then `outer` removes that entire inner container. A's test-only conflict chooser reports only `inner` because it selects shortest descendant distance, even though `outer` also destroys the old child. This is not a justified nested-slot ownership or diagnostic tie policy. No case reverses slot-name order so that the outer slot first removes the inner target and causes the later `unknownSlot` path.
5. **Nested ancestry: Layer nesting tested; Definition nesting separate.** A's strict descendant calculation distinguishes inner from outer slot targets and preserves the outside sibling write. B shows a Variant write to text inside a nested container is lost when the outer slot replaces children. These are nested Layers. They do not imply recursive Component Definition expansion.
6. **Valid nested Document and cycle: confirmed for the fixed model.** B supplies both A and B Definitions, unique IDs, a valid Scope, and a Screen using A. `DocumentValidator` emits no errors, `CanonicalRepository.commit` accepts, and reopen equals the candidate. Adding B→A yields three `component.cycle` diagnostics; commit rejects and the previously valid Document remains. Direct `ComponentResolver.resolve(A)` returns a `componentInstance` reference to B. A valid nested Document is therefore persistable, but direct Resolver recursion is absent.
7. **Canonical persistence: confirms current unsafe acceptance and fixed rejection.** B creates a real Repository for each case, validates, commits, and reopens. Selected Variant, property, empty slot, and nested-descendant writes into replaced content have no validation diagnostic and are **accepted** as Canonical Data; their resolved writes are absent. The later allowed override to a removed path is rejected with `component.resolution`. The unsupported container `.text` write is rejected with `component.variantPath` and `component.resolution`. For those rejected cases, B compares all non-`.hamii` `.json` path→bytes before and after and reports equality (787 bytes each), as well as old Document equality. The rejected A→B→A cycle similarly keeps Canonical JSON bytes equal (4,041 bytes). These byte checks concern this single-process, fixed-fixture attempt; they do not prove broader concurrent-write behavior or unchanged private coordination metadata.
8. **Claim strength and prototype safety: limited.** A's 13/13 result checks selected summary fields or error strings, not entire resolved Layer trees. A's `slotWins` and `conflictReject` are test-only preflights; they do not pass through `DocumentValidator` or Canonical storage. A's Definition also declares an unsupported `slotTargetText` property and public path, so the A fixture is not a valid whole Document. B's matrix checks selected resolved fields, validation diagnostics, commit outcome, and reopened Document equality; it does not exercise the GUI/CLI mutation entry points. No latency benchmark or production cache is present.

## Error priority is a correctness condition

The last two A cases are negative controls. A naïve `slotWins` drops a non-public `allowedOverride` before the Resolver checks its public API and reports `resolved`, suppressing production `forbiddenOverride`. It likewise drops two selected Variants writing the same path and suppresses production `conflictingVariants`. A naïve `conflictReject` returns `slotWriteConflict` before either existing error. Thus neither test-only strategy is production-safe without defining validation and diagnostic priority. The 13/13 pass records that these counterexamples were observed, not that a strategy was accepted.

## Decision inputs still needed

- Choose whether a valid write into content removed by a selected slot is invalid or an explicitly documented slot-wins operation. If rejecting, validate public API and same-path Variant conflicts before any slot-conflict diagnostic. If allowing slot-wins, make the suppression observable to authors and preserve existing invalid-input rejection.
- Define the diagnostic owner when nested selected slots overlap, and test the opposite application order. Test a valid ancestor write and a truly observable unselected Variant control without removing its target.
- Exercise the chosen rule through the full Document Validator, Canonical save, and common Application Service mutation path, comparing whole resolved trees and Canonical bytes where applicable. Keep recursive Definition expansion and cache/performance as separate unresolved questions.
